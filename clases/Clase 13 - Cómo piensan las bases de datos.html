01

Dato vs. información

`8`. Solo eso: el número 8. ¿Qué significa? Ahora agregale contexto: "la nota de Bruno en el segundo parcial fue 8". ¿Cambió el número, o cambió lo que podés hacer con él?

Un dato es un valor suelto, sin contexto: un número, una palabra, una fecha. Por sí solo no te permite decidir nada. La información es ese mismo dato interpretado dentro de un contexto que le da sentido — quién, cuándo, en relación con qué.

Una base de datos no junta información directamente: junta datos, organizados de una forma tan consistente que después se puede reconstruir la información a partir de ellos, cruzando lo que haga falta. Ese "organizados de forma consistente" es exactamente lo que esta clase define.

💡 Consejo

Cuando diseñes cualquier tabla de acá en adelante, preguntate: "si alguien mira esta fila sin ningún contexto más, ¿puede reconstruir la información completa?" Si la respuesta es no, probablemente falta un campo.

02

Campo, registro y tabla

Tu agenda de contactos del celular: ¿tiene una fila por contacto, y una columna por dato (nombre, teléfono, email)? Sin saberlo, ya usás una base de datos todos los días.

Una base de datos es un conjunto organizado de información, estructurado de forma que se pueda cargar, buscar y relacionar de manera consistente. Los tres conceptos básicos son siempre los mismos, cambie el programa que uses:

ConceptoQué esEjemplo
CampoCada tipo de dato que se registra (una columna)Nombre, Email, Carrera
RegistroUn conjunto completo de datos de un mismo elemento (una fila)Los datos de un estudiante en particular
TablaEl conjunto completo de registros con los mismos camposLa lista completa de estudiantes inscriptos

💡 Idea clave

Una planilla de Sheets bien armada (una fila por registro, una columna por campo, sin celdas combinadas ni filas vacías) ya cumple los requisitos mínimos para funcionar como una base de datos simple. La diferencia con un sistema de bases de datos más estricto es que ese sistema impone reglas duras sobre qué se puede cargar en cada campo — Sheets confía en que vos las respetes.

03

Tipos de datos

Si en la columna "Fecha de inscripción" alguien carga `15 de marzo` y otra persona carga `15/03/2026`, ¿Sheets los va a tratar como el mismo tipo de dato? ¿Y si en la columna "Edad" alguien escribe `veinte` en lugar de `20`?

Cada campo de una tabla tiene un tipo de dato: la clase de valor que ese campo puede contener. No es un detalle menor — el tipo de dato define qué operaciones podés hacer después (sumar, ordenar cronológicamente, filtrar por rango).

Tipo de datoEjemploQué falla si se mezcla
TextoNombre, CarreraNo se puede sumar ni ordenar numéricamente
NuméricoEdad, Monto, StockUn número cargado como texto (`"20"`) no suma ni promedia
Fecha/horaFecha de inscripción, Marca temporalFormatos distintos rompen el orden cronológico
Lógico (booleano)¿Activo? (Sí/No, Verdadero/Falso)Mezclar "Sí"/"Activo"/"1" impide contar de forma consistente
CategóricoCategoría, EstadoSin lista cerrada, aparecen variantes que `CONTAR.SI` no agrupa

⚠️ Atención

Sheets muchas veces "adivina" el tipo de dato según cómo lo escribís, y no siempre acierta. Un número alineado a la izquierda en la celda es una señal de que Sheets lo está tratando como texto, no como número — y eso rompe `SUMA`, `PROMEDIO` y cualquier función matemática.

04

La clave primaria

En una tabla de estudiantes, dos personas pueden llamarse "Juan Pérez". ¿Qué campo usarías para no confundirlos nunca, ni siquiera si comparten nombre, edad y carrera?

La clave primaria es el campo (o la combinación de campos) que identifica de forma única a cada registro de una tabla. Ningún otro registro puede tener el mismo valor de clave primaria, y ese valor no puede quedar vacío.

Qué hace buena a una clave primaria

RequisitoPor qué importa
ÚnicaSi dos registros comparten clave, ya no podés distinguirlos con certeza
No vacíaUn registro sin clave no se puede referenciar desde ningún otro lado
EstableNo debería cambiar con el tiempo — un nombre puede cambiar, un DNI o un legajo no

Ejemplos habituales de clave primaria: el DNI o legajo de una persona, el código interno de un producto, la marca temporal única de una respuesta de formulario.

⚠️ Atención

El nombre y apellido casi nunca es buena clave primaria — no es único (hay personas con el mismo nombre) y en teoría podría cambiar. Si tu tabla no tiene todavía un campo que sirva como clave, agregá uno artificial (un número de orden, un código correlativo) antes de seguir.

💡 Idea clave

La clave primaria de hoy es la misma pieza que en Clase 16 vas a ver del otro lado del espejo: cuando una tabla usa la clave primaria de otra tabla para referenciarla, a esa copia se la llama clave foránea. Todavía no necesitás ese término — alcanza con reconocer bien la clave primaria dentro de tu propia tabla.

Una sola idea para llevarte de esta clase

Antes de tocar cualquier herramienta, una base de datos ya existe en tu cabeza como modelo: qué campos importan, qué identifica sin ambigüedad a cada registro. Diseñar bien ese modelo es lo que evita rehacer todo después.
